1. What it does & who uses it

Spring PetClinic is a server-rendered web application for running a veterinary clinic. It manages pet owners, their pets (types, birth dates), the visits booked for those pets, and the clinic's veterinarians and their specialties. The UI is produced server-side with Thymeleaf over plain Spring MVC — there is no REST/JSON API; all interaction is HTML form-driven.

Users: clinic front-desk / administrative staff who register owners, add pets, book visits, and look up vets. As the canonical Spring Boot reference app, a second audience is developers learning Spring Boot / Data JPA / Thymeleaf. There is no login or role system — every visitor has full access.

3. Execution flow — adding a new visit

POST /owners/{ownerId}/pets/{petId}/visits/new

  1. DispatcherServlet routes the request to owner/VisitController.java.
  2. @ModelAttribute pre-handlers run first. VisitController.loadPetWithVisit(ownerId, petId, model) (VisitController.java:63-81) calls OwnerRepository.findById(ownerId) (OwnerRepository.java:60), resolves the pet via Owner.getPet(petId) (Owner.java:117), constructs a new Visit() (Visit.java:48, date defaults to tomorrow), attaches it with Pet.addVisit(visit) (Pet.java:81), and exposes it as model attribute "visit". minVisitDate() (VisitController.java:83-86) supplies tomorrow for the form.
  3. @InitBinder setAllowedFields (VisitController.java:51-54) disallows binding id/*.id; form fields bind onto the Visit.
  4. Handler VisitController.processNewVisitForm(...) (VisitController.java:97-112): @Valid applies @NotBlank description (Visit.java:42); a manual future-date check (VisitController.java:100-102) rejects non-future dates. On error → view pets/createOrUpdateVisitForm.
  5. Persist. On success, Owner.addVisit(petId, visit) (Owner.java:164-174) re-resolves the pet and adds the visit, then OwnerRepository.save(owner) (VisitController.java:109).
  6. Cascade INSERT. save cascades Owner.pets → Pet.visits (both CascadeType.ALL, Pet.java:56-59); Hibernate inserts into the visits table.
  7. Adds flash message "Your visit has been booked" and returns redirect:/owners/{ownerId}.

4. Build / test commands & default database

Build & test (Maven and Gradle both supported)

./gradlew bootRun        # ./mvnw spring-boot:run    → http://localhost:8080
./gradlew build          # ./mvnw verify             full build + tests
./gradlew test           # ./mvnw test               all tests
./gradlew test --tests OwnerControllerTests          # single class (Gradle)
./mvnw test -Dtest=OwnerControllerTests              # single class (Maven)
./mvnw package -P css                                # recompile SCSS→CSS (Maven only)

spring-javaformat + nohttp/checkstyle run at Maven's validate phase / Gradle checkstyle* tasks and fail the build on violation. Auto-fix with ./mvnw spring-javaformat:apply or ./gradlew format.

Default database

In-memory H2, configured in application.properties:1-4: database=h2 selects db/h2/schema.sql + db/h2/data.sql, run at startup. spring.jpa.hibernate.ddl-auto=none (schema comes from SQL scripts, not Hibernate) and open-in-view=false. Switch with spring.profiles.active=mysql or =postgres (application-mysql.properties / application-postgres.properties); docker compose up mysql|postgres starts a matching DB.

5. Risks, gaps & weak spots

Security

SECURITY Actuator fully exposed

application.properties:21 — management.endpoints.web.exposure.include=*. The in-file comment itself warns "Don't do this in production." Exposes /actuator/env, /actuator/heapdump, etc. to anonymous callers.

SECURITY No authn/authz & no CSRF

No Spring Security on the classpath: every owner/pet/visit edit endpoint is open and the POST forms in OwnerController, VisitController, PetController have no CSRF protection.

SECURITY Intentional crash endpoint

system/CrashController.java:31-35 (/oups) throws an unhandled RuntimeException by design — fine as a demo, should not ship in production.

Validation gaps

VALIDATION Pet birth date unchecked

owner/PetValidator.java:51-53 only rejects null; Pet.birthDate (Pet.java:48-50) has no constraint, so future or implausibly old dates are accepted.

VALIDATION Visit-date rule lives in the controller

Visit.date (Visit.java:38-40) has no @Future; the rule is hand-coded in VisitController.java:100-102 and duplicated against minVisitDate() (VisitController.java:83-86). Any other save path bypasses it.

VALIDATION Brittle phone pattern

Owner.telephone uses @Pattern("\\d{10}") (Owner.java:61) — exactly 10 digits, no country codes or formatting.

Error handling

ERROR HANDLING Missing entity → 500, not 404

OwnerController.findOwner (OwnerController.java:65-70), showOwner (:170) and VisitController.loadPetWithVisit (:67, :72) throw IllegalArgumentException for unknown IDs, surfacing as a generic 500 page rather than a 404.

Configuration / data integrity

CONFIG Eager collections

Owner.pets (Owner.java:64) and Pet.visits (Pet.java:56) are FetchType.EAGER with open-in-view=false; over-fetch / N+1 risk as data grows (partly mitigated by default_batch_fetch_size=16).

CONFIG Redundant repository method

OwnerRepository.findById (OwnerRepository.java:60) re-declares a method JpaRepository already provides.

Test coverage

TESTS Untested = exactly the gaps above

Web-slice tests exist (OwnerControllerTests, VisitControllerTests, PetControllerTests, VetControllerTests; service/ClinicServiceTests for persistence), but there is no test asserting an invalid Pet.birthDate is rejected (nothing rejects it) nor that not-found IDs return a 404.
